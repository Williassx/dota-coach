# Навыки для планирования и разработки

В проект добавлен порядок применения существующих навыков Superpowers.
Это инструкции выбора навыков; они доступны через установленный плагин в текущей
сессии. Копии плагина и новые модели ИИ не устанавливались. В другой среде агент
сначала проверяет наличие навыка и читает его актуальный SKILL.md.

## Навыки создания плана

| Навык | Когда применять | Ожидаемый результат |
|---|---|---|
| `superpowers:brainstorming` | Новая подсистема, механика или изменение архитектуры | Понятная цель, альтернативы, границы, сценарии и рассмотренная спецификация |
| `superpowers:writing-plans` | Спецификация рассмотрена, нужна очередь реализации | Точные файлы, интерфейсы, зависимости, тесты, команды и критерии отдельных задач |
| `superpowers:dispatching-parallel-agents` | Разрешено делегирование и есть независимые задачи | Разделение ответственности без конфликтов состояния и файлов |
| `superpowers:verification-before-completion` | Перед заявлением о готовности документа или результата | Проверенные ссылки, зависимости, покрытие требований и фактические результаты |

Первый навык отвечает за то, что строить; второй — за точный порядок реализации.
Общая дорожная карта разделяет проект на подсистемы и не заменяет эти два документа.

## Навыки выполнения и проверки

| Навык | Когда применять | Ожидаемый результат |
|---|---|---|
| `superpowers:executing-plans` | Основной агент выполняет рассмотренный план | Последовательное выполнение задач с проверками |
| `superpowers:subagent-driven-development` | Выбрано и разрешено выполнение через подагентов | Исполнитель и независимая проверка задач |
| `superpowers:test-driven-development` | Реализация логики симуляции, команд и преобразования данных | Проверка требуемого поведения до реализации и после неё |
| `superpowers:systematic-debugging` | Необъяснённый сбой теста, импорта, ИИ или запуска | Проверенная причина и направленное исправление |
| `superpowers:requesting-code-review` | Завершена значимая часть реализации | Проверка соответствия требованиям и качества |
| `superpowers:receiving-code-review` | Получены замечания | Проверка обоснованности и исправление подтверждённых проблем |
| `superpowers:verification-before-completion` | Перед заявлением о работающей функции | Команды выполнены; пройденные, упавшие и непроведённые проверки различены |

Для обновления облачной среды применяется `cloud-environment-onboarding:setup`:
установка, запуск и сохранение воспроизводимых инструкций. Работать в текущем
изолированном checkout; Git worktree создаётся по явному запросу пользователя.

## Предметные компетенции для этого проекта

Это требования к исполнителям задач, а не названия дополнительно установленных навыков.

| Компетенция | Где нужна | Что исполнитель должен учитывать |
|---|---|---|
| Анализ событий и реплеев Dota | P01, P04 | Патчи, формат, идентификация, пропуски, происхождение данных |
| Моделирование поведения и обучение | P02, P06 | Разделение матчей, база сравнения, неопределённость, перенос в другую симуляцию |
| Игровой ИИ и симуляция | P03, P05, P10 | Воспроизводимость, доступные наблюдения, правила, производительность |
| Распознавание речи | P08 | Настоящий голос, неоднозначность, задержка, микрофон, сеть и альтернативный ввод |
| Интерактивная карта и управление | P07, P11 | Координаты, выбор цели, режимы управления, возврат ИИ |
| Лицензирование Dota, данные и личность игроков | P01, P03, P13 | [Юридическое направление](legal/plan.md), первоисточники, применимое право и условия конкретного использования |

## Проверка плана перед передачей исполнителям

1. Цель соответствует замыслу пользователя: цифровые игроки, подготовка, голос,
   временное вмешательство и разбор присутствуют.
2. Пользовательские решения отделены от предложений по платформе и моделям.
3. Каждая задача даёт наблюдаемый результат и содержит проверяемые критерии.
4. Зависимости не образуют цикл; параллельные задачи имеют согласованные интерфейсы.
5. Карта содержит игровую модель; визуальный референс не подменяет её.
6. Достоверность профилей проверяется отдельно от работоспособности симуляции.
7. Недостаток данных и неподтверждённые права не объявляются решёнными.
8. Команды проверки и точные файлы закрепляются в плане конкретной подсистемы.

## Где создавать следующие документы

По новому поручению пользователя работа сначала ведётся в библиотеке создателя:
`creators/creator-N/NN-section/NN-subsection/design.md` и
`creators/creator-N/NN-section/NN-subsection/implementation-plan.md`.
Навигация и правила: [creators/README.md](../creators/README.md),
[WORKFLOW.md](../creators/shared/WORKFLOW.md). Общие решения остаются в `docs/`.
Каждый план ссылается на свою рассмотренную спецификацию; дата соответствует
дате создания. На каждый крупный этап отдельный план: данные, симуляция,
персональный ИИ, управление, полный матч и карьера.

Юридические роли 161–172 — специализации исследования. Они не являются
дополнительно установленным юридическим плагином или профессиональным допуском.
