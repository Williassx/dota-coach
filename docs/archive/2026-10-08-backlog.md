## Пакеты работы

1. **Проектирование:** MVP-01–06. Результат — согласованные правила и технический план.
2. **Симуляция:** MVP-07–15. Результат — матч, которым можно управлять без графического интерфейса.
3. **Игровой экран:** MVP-16–19. Результат — первый матч по исходному эскизу.
4. **Проверка:** MVP-20–23. Результат — проверенный прототип с инструкциями запуска.

После определения общих интерфейсов MVP-16 можно выполнять параллельно с
MVP-11–15. Изменения общих типов согласуются с владельцем модели данных (102).
Остальные задачи запускаются согласно зависимостям, без одновременного редактирования
одних файлов независимыми исполнителями.

## Проверки, которые нужно закрепить в спецификации

- Повторный старт не создаёт дополнительный таймер симуляции.
- Во время паузы не изменяются время, позиции, здоровье и ресурсы.
- Смена скорости меняет темп отображения, сохраняя правила расчёта.
- Приказ погибшему игроку или по отсутствующей цели получает определённый ответ.
- Команда «фармить» имеет доступную цель и наблюдаемый результат.
- Новый матч сбрасывает выбор, приказы, журнал и итог предыдущего матча.
- Условие победы разрешается однозначно, включая одновременное уничтожение баз.
- Матч имеет определённое завершение при отсутствии прогресса.
- Уверенность и настрой на карточках имеют описанный смысл; влияние на поведение
  включается только по правилам спецификации, без случайных неподтверждённых бонусов.

## Учёт выполнения

Все MVP-01–23 имеют статус «запланировано». При начале задачи исполнитель
фиксирует статус и область изменений; при завершении — проверки и результат.
Документация планирования не считается выполненной реализацией.
