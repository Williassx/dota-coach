# C1-02-01: жизненный цикл запуска (серверный)

Спецификация по фактам [notes/lifecycle.md](notes/lifecycle.md).
Цель приёмки: «Перезапуск не дублирует события, таймеры и состояние прошлого матча».

## Подход

Отдельный аддон `dota_coach_c1_lifecycle_<дата>` с единственным Lua-скриптом
серверного жизненного цикла (исходники в `src/` этого подпункта):

1. **Активация однократна.** Глобальный флаг `_G.D1C201_ACTIVE` ставится в
   `Activate()`; повторный вызов `Activate()` в том же процессе не создаёт
   второй game mode и не регистрирует второй Think (лог `D1C201 double-activate
   ignored`).
2. **Регистрация чиста.** Имя Think сохраняется у объекта; обработчик state-фаз
   использется один — печать фазы через `PrintEvents`-подобный вывод не дублируется:
   лог `D1C201 phase <STATE>` появляется по одному разе на фазу в логе.
3. **Остановка честна.** В `POST_GAME` Think печатает `D1C201 stop` и возвращает
   `nil`: после остановки тиков быть не должно; тест лога это проверит.
4. **Состояние прошлого матча не наследуется.** Все поля режима создаются внутри
   `Activate()` нового объекта; глобального кеша юнитов/таймеров нет; при повторном
   запуске в новом процессе лог начинается с `precache → activated` без «старых»
   записей.

## Границы

- Перезагрузка карты в одном живом клиенте — открытый вопрос; приёмка «два
  последовательных запуска» выполняется как два свежих процесса (подтверждённый
  порядок создателя 2), а не как +restart в живом клиенте.
- Владение игроком не входит (открытая позиция C1-01-03).
- Тесты — статические и на структуру лога: поведение подтверждается нативным
  прогоном отдельно (r-цикл как в C1-01-02) и не объявляется до запуска.
