# C1-02-03: время и журнал событий (факты и подход)

Дата: 13 октября 2026. Основание — behaviour-факты прогонов r1–r8 и шаблонного
Think-цикла ([отчёты](../../01-foundation/02-addon-capability/reports/),
[lifecycle](../01-session-lifecycle/reports/lifecycle-r6-r7-20261013.md)).

## Подтверждено

- Пульс серверной логики: `SetThink(…, 1)` даёт ровный секундный тик; Think
  честно останавливается `return nil` в POST_GAME (r6/r7: отсутствие
  `tick-after-stop` — нативный факт).
- Правила состояний наблюдаемы по одному разе при honest записи
  (`phaseSeen[state] ~= true`): записи прошли 5 фаз до `GAME_IN_PROGRESS`,
  после — как в отчёте C1-02-01.
- Реальное игровое время и пауза шаблонным сценарием не проверялись; в
  проверках r1–r7 фактически тайминги оценивались wall-часами логов
  ([вопросы точного clock](../../01-foundation/03-command-contract/notes/contract-review.md)).

## Подход к журналу (черновик, договор фактически после факта clock)

Событие журнала — строка с полями: `seq`, `gameTimeOrWall` (выбор источника —
после факта: не выдумывать API — сначала проверяем доступность игрового времени
нативным сообщением), `type`, `actorRef`, `payload`. Свежая запись не повторяет
прошлого матча — формат обязан быть совместимым с guard-ами жизненного цикла
(единственные тики, единственные фазы).

## Сопоставление с критерием (pure-уровень, 13 октября 2026)

Связь команд, режимов и наблюдаемых действий закрыта конструкцией:
`LinkOrder` сводит приказ к записям, `TagMode` метит режим (AI/MANUAL),
`GetByOrder` восстанавливает цепочку. Реализация —
`src/scripts/vscripts/event_log.lua`, проверки 5/5 OK.
Не проведено: проверенное игровое время и поведение паузы (нативный
эксперимент), предел времени вмешательства, передача создателю 2;
пауза не расходует время — не заявляется.

## Открытые вопросы

- Источник игрового времени (какой фактический API доступен и останавливается
  ли при паузе) — нативный эксперимент r-цикла; до факта приёмка «пауза не
  расходует время» не заявляется.
- Пределы времени боя (таймеры вмешательства) — предмет C1-04-x, здесь фиксируем
  только журнал; «порядок событий» проверяется на единственной записи фазы.

## Стыки

- C1-01-03: время защит от «устаревших приказов» остаётся открытой позицией
  контракта; при определённом источнике времени — связывается в ревизии.
- C1-02-01: повторная активация не должна менять подряд упомянутые структуры
  журнала past-match.
