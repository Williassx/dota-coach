# C1-02-02: привязка актора (факты и план эксперимента)

Дата: 13 октября 2026. Только подтверждённые факты из прогонов r1–r5 и механика
жизненного цикла r6–r8 ([документы](../../../01-foundation/02-addon-capability/reports/)).

## Подтверждено

- Серверный `CreateUnitByName(..., owner=nil)` даёт владельца `-1`; neither
  `SetControllableByPlayer(0, true)` nor `SetOwner(PlayerResource:GetPlayer(0))`
  меняют его по `GetPlayerOwnerID()`.
- `PlayerResource:GetPlayer(0)` возвращает объект (строка `player-missing` не
  появлялась) — human seat 0 в матче `dota_launch_custom_game` существует.
- Наш think-цикл жив внутри сервера; авто-аггро может перекрыть приказ (r5).

## Открытые вопросы (эксперимент r6-actor, не изобретать результат)

- Действительно ли создаётся штатный герой человеческого seat при старте
  custom game, и как попросить движок сделать это, если нет (стандартный
  механизм — отдельный эксперимент; видимо, подход — не переприсвоение).
- Связь постоянного «ID виртуального игрока» проекта (данные тренерской модели,
  C1-06/C2-04-01) и seat-индекса — черновая пара «проектный постоянный ID ↔
  seat/engine index» записывается только после факта: сущность и владение
  (как в r1-r5 identity-логе).

## План минимального seat-эксперимента (что проверяем)

1. Новый аддон (по рецепту lifecycle): печать фактических данных seat 0 через
   действительные API (количество игроков, команда seat 0); каждая строка —
   дополнительный факт. Подписи API закрепляются после проверки, не выдумываются.
2. Запуск r удалить-установить (lifecycle-рецепт), 2 ряда (r9/r10), quit по receipt.
3. Записать факты и констатацию, не успех; путь реализации привязки — после
   факта hero-seat.

## Стык с C1-01-03

Контракт приказов ссылается на «актёра = EntityIndex», но «передача управления
тому же герою» закрыта не будет до факта seat-героя; открытый вопрос в
[contract-review](../../../01-foundation/03-command-contract/notes/contract-review.md)
остаётся; seat-факт станет дополнением к нему.

## Сопоставление с критерием (pure-уровень, 13 октября 2026)

Критерий «приказы старой привязки не воздействуют на нового героя; чужое
назначение отклоняется» выполнен конструкцией: тройка ID/seat/entity +
ревизии (`Accepts`), занятость seat/entity (`seat-or-entity-taken`),
проверка владельца из доверенного события (`CheckOwner`), смерть гасит
привязку (`OnDeath`), возрождение требует явной перепривязки
(`OnRespawn`), сдвиг seat отклоняется (`seat-moved`).
Реализация — `src/scripts/vscripts/actor_binding.lua`, проверки 7/7 OK.
Не проведено: seat-герой r9/r10, движковое владение, авто-аггро,
передача создателю 2.
