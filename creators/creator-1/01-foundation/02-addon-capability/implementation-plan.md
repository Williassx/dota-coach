# C1-01-02: технический план минимальной серверной сцены

> Для агентной работы: использовать `superpowers:executing-plans`; каждый запуск
> Dota проверяется фактом логов, процесс запуска сам по себе не засчитывается.

**Цель:** подтвердить на реальном клиенте серверный приказ движения/атаки и
лог-подтверждение идентичности героя.
**Спецификация:** [design.md](design.md). **Изучение шаблона:** [notes/capabilities.md](notes/capabilities.md).
**Технологии:** Lua vscripts Dota; Python unittest для статических проверок исходников;
Установка в игру — отдельная команда копирования, пользователь подтвердил использования
компьютера под задачи кастомки.

## Ограничения

- Один штатный герой: `npc_dota_hero_sniper` (штатное имя движка).
- Цель движения — фиксированная точка; цель атаки — вторая созданная юнит той же
  модели на противоположной команде; не обходимся без файлов контента.
- Изменение существующих аддонов и файлов Dota запрещено; копия карты шаблона —
  штатная `addon_template/maps/template_map.vmap` (без пересборки: причина
  ERROR_FILEOPEN базовых ресурсов зафиксирована у создателя 2).
- Запуск dota2.exe не считается успехом без подтверждения в логах.

## Серверный скрипт — фактические API

- Точки входа по шаблону: глобальные `Precache(context)`, `Activate()`.
- Лог-префикс подтверждения: `print("D1C102 activated")` в `InitGameMode()`.
- Создание юнита: `CreateUnitByName(unitName, Vector(x, y, 0), true, nil, nil,
  teamOwner)`; пара юнитов: `DOTA_TEAM_GOODGUYS` (сценовый герой) и
  `DOTA_TEAM_BADGUYS` (цель атаки) создаются рядом в разных точках.
- Приказ движения: `ExecuteOrderFromTable({ UnitIndex = <индекс>, OrderType =
  DOTA_UNIT_ORDER_MOVE_TO_POSITION, Position = <Vector>, Queue = false })`.
- Приказ атаки: тот же метод с `OrderType = DOTA_UNIT_ORDER_ATTACK_TARGET` и
  `TargetIndex = <индекс цели>`.
- Наблюдение: SetThink каждые 1.0 с: печать `D1C102 state <idx> origin=<...
  enemyIndex=<>` `GetAbsOrigin()` юнита и факт изменения координат.
- Индексы кэшируются; при смерти/удалении — повтор не выдается, юнит не воссоздается.

## Сценарии статических проверок (tests)

1. Скрипт содержит префикс `D1C102 activated` и фильтр неожиданных приказов отсутствует
   (не претендует на C1-01-03).
2. Используются только `DOTA_UNIT_ORDER_MOVE_TO_POSITION` и
   `DOTA_UNIT_ORDER_ATTACK_TARGET`.
3. Оба приказа идут через `ExecuteOrderFromTable`, а не прямые вызовы выключенных API.
4. Нет обращений к сети, файлам или пользовательским данным.
