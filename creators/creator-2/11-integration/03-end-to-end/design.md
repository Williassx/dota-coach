# Единый прогон исходников C2-11-03

Пользователь поручил продолжать самостоятельно и уменьшить повторение контекста.
Сейчас 34 обязательных набора перечисляются заново в командах и настройке среды.
Ведущий — основной исполнитель отдела 2; отдельный критик только после подпроекта.

Один JSON-каталог хранит ID, framework и относительный путь каждого набора.
Помощник строит только Node test/TAP или Python unittest discover команды без shell.
Python запускается текущим интерпретатором, Node ищется через PATH. Полный прогон
по умолчанию; повторяемый `--suite` позволяет целевую проверку. Каталог включает
собственные тесты помощника; они запускают маленькие fixtures, а не весь каталог.

До записи проверяются каталог, выбор, инструменты, пути и параметры. Переиспользуется
защита путей исходного builder: portable paths, symlink/reparse и новый каталог
только под `build/dota_coach`. Существующие результаты сохраняются. Независимые
наборы выполняются до семи workers, по умолчанию четыре. Timeout отдельного набора
и отсутствие строгого итогового summary означают отказ, даже при exit 0. Пропуск,
cancelled и todo также не проходят. Полные логи пишутся в файлы, JSON хранит итоги;
stdout — короткое резюме и ID ошибок. Частичный прогон явно обозначается.

Это проверка исходников, не клиентская сквозная приёмка: Source 2, сцена Dota,
микрофон, сервер и другой владелец остаются непроверенными. Число тестов и длина
вывода не являются измерениями токенов. Исходники другого отдела не меняются;
его существующий аудит включается в обязательную read-only регрессию.
