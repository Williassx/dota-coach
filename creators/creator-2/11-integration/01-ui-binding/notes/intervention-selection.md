# Подключение локального координатора выбора

[Подпункт](../README.md) · [Дизайн](../intervention-selection-design.md).

Порядок определений: roster_cards_state.js, orders_state.js,
intervention_request_state.js, intervention_selection_state.js. Затем явно вызовите
DotaCoachInterventionSelection.create(adapterConfigured), где только true включает
создание локальных предложений. Эти определения не создают панели и не отправляют
сетевые или игровые команды.

replaceRoster(rows) принимает список через существующий Roster. selectPlayer(id)
выбирает карточку; updateControl(frame) передаёт снимок только в Requests. Порядок
получения карточки/снимка не важен: выбранная карточка сохраняется без снимка,
возможность begin появляется только при согласованной доступности обеих моделей.
Снимок другого игрока не выбирает его автоматически.

view возвращает независимые roster/manual и объединённый canRequest. Dead карточка
доступна для просмотра, но запрещает begin даже при прежнем alive-снимке. Неверный
список сохраняет предыдущие карточки, закрывая gate до принятого списка. Roster
не имеет revision/epoch: порядок поставки обязан обеспечить источник; старый
структурно правильный список локально может быть принят снова. Это не доказательство
актуальности или разрешение управления реальным героем.

begin возвращает existing localintent; отправка выполняется вызывающей стороной.
report/expire/notSent сохраняют правила Requests. Смена выбора или удаление карточки
не меняет capturedactor. ACK не меняет режим, наблюдение MANUAL не выдаёт право ввода,
неизвестный исход блокирует повтор. notSent требует доказанной неотправки.

Если общий gate закрылся после terminal результата, оба сообщения сохраняют
captured name/ID/reason и объясняют блокировку без предложения нового запроса.
Busy view скрывает обе модели; вложенные DTO не читаются, dispose побеждает getters.
Dispose закрывает локальные модели, а не отменяет серверный запрос.

Панели/HUD/пакет, actualtransport/authority/lease/возврат ИИ, native и второй владелец
остаются открытыми. Реальные персональные модели игроков здесь не проверяются.
