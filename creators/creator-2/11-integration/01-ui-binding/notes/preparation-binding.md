# Общая привязка подготовки

[Подпункт](../README.md) · [Дизайн](../preparation-binding-design.md).

`DotaCoachPreparationBindings.bind(root)` требует уже существующие отдельные области
TeamPickerRoot, HeroRoleRoot, PreparationRoot и CoachPreparationStatus. Загрузите port,
три модели и их адаптеры, flow и binding в одном контексте. Определения инертны;
bootstrap, общий XML и пакет ресурсов здесь ещё не созданы.

Одна частная цепь владеет состоянием. API: updateTeam/choosePlayer/removePlayer/clearTeam,
updateHeroes/assignHero/removeHero/clearHeroes, updatePreparation/choosePlan/chooseTalk/
removePlan/removeTalk/clearPreparation; contexts/draft, selectHeroPlayer, refresh,
dispose/isDisposed. contexts возвращает копии {team,heroes,preparation}; draft доступен
только при полной локальной подготовке. serverConfirmed всегда false.

Смена состава сразу очищает героев и подготовку. Смена назначений очищает подготовку.
На время чтения DTO все три панели приостанавливаются: подписи очищены, кнопки
отключены, общий статус сообщает обновление. Вложенные изменения отклоняются до
чтения их данных. После операции панели обновляются; фокус героя сохраняется только
при совпадении id и версии. При закрытии любой области закрывается вся привязка.

Адаптеры поддерживают прежний bind(root), а bind(root,projection) принимает принадлежащую
им проекцию с собственными функциями без accessor. projection нельзя одновременно
передать двум панелям. refresh перерисовывает, suspend очищает показ без потери фокуса
и страницы. Dispose проекции вызывается один раз, исключение не прерывает очистку UI.

Внутренний invoke инициирующей панели может вернуть false после принятого изменения:
общая перерисовка уже сменила поколение этой панели. Обработчик клика не использует
этот результат; публичный group API возвращает результат flow при актуальной отрисовке.
Внешний код должен пользоваться group API, закрытые child handles ему не выдаются.

Четыре таймера проверяют только lifecycle. Частичный отказ не закрывает отдельно
привязанную чужую панель; старые обработчики и таймеры не влияют на новую привязку.
Native компоновка, загрузка и hittest, C1/реальные каталоги/эффекты/сервер,
персональное сходство моделей и проверка второго владельца остаются открытыми.
