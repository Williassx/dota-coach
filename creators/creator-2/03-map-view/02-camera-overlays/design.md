# C2-03-02: отдельный запрос фокуса камеры

Пользователь поручил непрерывную автономную работу создателя 2. Подготовим
небольшую панель фокуса героя своей команды, отдельно от выбора/приказа/режима управления.
Карта и нативная интеграция остаются открытыми; маркеры мира здесь не реализуются.

## Выбранный объём

Постоянное слежение SetCameraTarget потребовало бы владения блокировкой/сбросом
камеры. Позиционные маркеры потребовали бы проверенной геометрии/обзора.
Используем штатный GameUI.MoveCameraToEntity(entityIndex): декларация ModDota
указывает, что он перемещает камеру к сущности без блокировки слежения.
Вызов только после явного клика; обновление выбора камеру не двигает.

Декларации закреплены commit df7722b560d5c616f7b2f6be42480aa5053baec8,
packages/panorama-types/types/api.d.ts. Это community reference, не Windows/runtime proof.
Данные цели — частная UI-проекция {id,playerName,entityIndex}, не сетевой контракт.
Связь stableid→entity проверит будущий переходник; имя не идентифицирует юнит.

## Интерфейсы

- DotaCoachCameraNative.create() → {check(entityIndex),focus(entityIndex)}.
  check возвращает {available:boolean,reason:string|null}; focus —
  {requested:boolean,reason:string|null}. Каждый вызов проверяет индекс, локального
  playerID, команду 2/3, IsValidEntity/IsRealHero/IsAlive и совпадение GetTeamNumber.
  При недоступном API/сущности возвращает отказ, не выдумывает успех.
  focus повторяет check непосредственно перед MoveCameraToEntity.
  playerID int 0..63, native predicates строго boolean true. Причина отказа —
  непустая непробельная строка до160, при available/requested=true reason=null.
  Отсутствие MoveCameraToEntity проверяется до включения кнопки.
- DotaCoachCameraPanels.bind(root,gateway?) → setTarget(input):bool,
  refresh():bool,dispose():void,isDisposed():bool.
  Без gateway с функциями check/focus кнопка отключена. Target=null снимает выбор.
  Остальные данные ровно три поля: непустой id/name до64, id без пробельных краёв,
  entityIndex int 0..2147483647. Вход копируется; неверный сохраняет предыдущую цель.

Root содержит CameraRecipient, CameraAvailability, CameraResult и CameraFocus.
Labels html=false. Один живой адаптер на root; dispose освобождает обработчик
и владение. XML/CSS — исходники компонента, без demo/bootstrap и автоматического bind.
Для HUD нужны явно переданные root/gateway/данные, отдельные от roster/orders.

## Поведение и ошибки

Рендер проверяет доступность цели через check без перемещения. Перед кликом снова
проверяются актуальный root, поколение отображения и gate; native focus повторяет
проверку живого своего героя. Старый callback после смены цели/refresh/dispose
не перемещает камеру. Смерть, удаление, другая команда, spectator/неизвестная local
team блокируют действие. Enemy origin/скрытые позиции и приказы юнитам не читаются.

Проверяются только копии результатов check/focus, с точными полями/boolean/reason.
Во время чтения входа/gateway-result возможен повторный вход: после copy проверяется
closed/generation; закрытый адаптер не рисует поверх нового. Невалидный ответ/сбой
рендеринга закрывает панель с отключением кнопки. Исключение focus означает
«запрос не подтверждён; положение камеры неизвестно», не успешное перемещение.

Requested означает, что native функция вызвана без исключения: прибытие камеры
не подтверждено. Результат показывает имя исходной цели отдельно от текущего выбора;
смена карточки не выдаёт прежний фокус за действие для нового игрока. При совпадении
имён сравниваются stable id и entityIndex: результат другой цели подписан
«Предыдущий выбор». Проверяется принадлежность команде, а не владение одним героем.

## Проверки и границы

node:test/vm исполняет реальные ES5: no auto-focus, own alive realhero guard,
неизвестный API/данные, повторная проверка, старые callbacks, plain-text имена,
invalid/results/reentrancy/dispose/partial bind. GameEvents/мышь/приказы/позиции
перехватываются как запрещённые. XML ссылки/ids/styles/scripts проверяются отдельно.
VM не подтверждает MoveCameraToEntity в установленной Dota, совпадение выбранного
игрока с объектом, поддержку кастомного hero, camera bounds или hittest.
Маркеры, масштабирование, источник наблюдений, общий HUD и второй владелец открыты.
