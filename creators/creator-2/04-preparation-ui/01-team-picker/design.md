# C2-04-01: локальный черновик пяти разных игроков

## Цель и границы

Пользователь хочет собрать перед матчем команду из разных цифровых игроков.
Первый независимый шаг — проверяемая локальная модель выбора без сервера и bootstrap.
Реальные модели/данные, подтверждение сходства и C1-07-01 отсутствуют. Не объявлять
пять локальных выборов готовой командой для запуска игры.

Архитектурная задача: одна ES5-модель в библиотеке создателя 2. Применены
brainstorming/writing-plans; пользователь ранее поручил автономное продолжение
без рутинного согласования, поэтому дизайн/план проверяют пять read-only критиков.

Альтернативы: немедленный серверный состав зависит от неподготовленного C1-контракта;
полный экран выбора потребует отдельного panel/lifecycle слоя. Сейчас выбран локальный
черновик как ограниченная первая часть, затем панель и серверная интеграция.

## Единственный исходник и API

`src/panorama/scripts/custom_game/team_picker_state.js` определяет
`DotaCoachTeamPicker.create()` → update, choose, remove, clear, view, draft,
dispose, isDisposed. Никаких native API, timers, network/storage, отправки или матча.
Definitions не включаются в HUD, пока не подготовлен самостоятельный экран.

## Частная проекция каталога

`update({revision, profiles})`: точные два поля, revision целое 0..9007199254740991,
profiles — максимум 64 записи, stable ids уникальны. Каждая запись имеет ровно:

- id: строка 1..64 с непробельными символами, без крайних пробелов;
- playerName: непробельная строка 1..64;
- profileVersion: строка 1..64, без крайних пробелов;
- kind: synthetic или player_model;
- sourceLabel: непробельная строка 1..160, просто текст источника;
- coverage: unknown, limited или reported.

Это частная UI-проекция, не общий серверный контракт. player_model означает только
тип записи, переданный источником, а не проверенное сходство. reported — источник
сообщил охват; это не поддержка конкретного героя/роли/патча и не авторизация.
Синтетические fixtures не используют реальные имена/модели.

Невалидный новый снимок снимает каталог и черновик. Валидный revision потребляется
до чтения profiles; old/duplicate не читают body и не восстанавливают данные после
отказа. Пока снимок разобран не полностью, выбор недоступен. Newer reentrant update
имеет приоритет; старый вызов не перезаписывает его. Getter dispose не восстанавливает
данные. Schema rejects non-enumerable extras; тексты не интерпретируются как HTML.
Нет local TTL: это черновик, freshness и server readiness не заявляются.

## Пять разных игроков

choose(id) выбирает присутствующий id: максимум пять, без дублей. Повтор возвращает
false без изменения draftRevision. remove(id) убирает конкретный выбор, clear()
снимает все; пустой clear успешен без увеличения draftRevision.
Выбор сохраняется при новом каталоге только для того же id и profileVersion.
Изменение версии/удаление профиля снимает его и требует нового явного выбора.
Порядок выбора сохраняется; не назначаются роли, герои, реальные команды или слоты
матча. Coverage не блокирует исследовательский выбор, но всегда видно предупреждение.

view() отдаёт независимые копии {status, message, profiles, selected, count,
complete, warnings}. status: empty, ready, invalid, disposed. ready означает наличие
валидного каталога, не игровую готовность. complete означает только count===5.
Для любого player_model: «Сходство модели игрока здесь не проверено.»;
synthetic: «Используется синтетический профиль.»;
unknown: «Охват данных неизвестен.»; limited: «Источник сообщает ограниченный охват.»;
reported: «Охват указан источником; роль, герой и патч здесь не проверены.».
Warnings — независимые {id,text}, без неподтверждённых процентов или характера.

Для валидного каталога draft() отдаёт независимый объект {catalogRevision,
draftRevision, complete, serverConfirmed:false, players:[{id,profileVersion}]}.
При empty/invalid/disposed — null. draftRevision монотонно увеличивается только
при изменении выбранных id/version, включая снятие из-за update/dispose; без wrap.
Если счётчик исчерпан, модель закрывается, не выдавая прежний draft как новый.
Сохранение только в памяти, без заявлений о persistence между сессиями.

## Приёмка этой части

RED до source, затем проверки уникальности/лимита/версий/плохих проекций/high-water/
reentry/immutability/warnings/dispose. Пять критиков, общий регресс, syntax/README/links,
отдельный журнал и fast-forward Git. UI/сервер/герои/роли/native/второй владелец открыты.

## Уточнения до реализации

id — устойчивый виртуальный игрок, не hero/model variant/version. Два варианта
одного игрока обязаны иметь тот же id, поэтому каталог отклоняет их как повтор.
Разные id с одинаковыми именами допустимы; источник ещё должен подтвердить их связь
с людьми. Локальная уникальность не доказывает пять разных реальных лиц.
view.selected — полные независимые копии выбранных профилей в порядке выбора.
Warnings относятся только к selected; по два предупреждения на id, сначала kind,
затем coverage, порядок выбора стабилен. Каталог содержит исходные kind/coverage
для будущей панели, никаких автоматических оценок.
Message после валидного каталога: «Каталог загружен; состав не подтверждён.»;
после пятого выбора: «Выбрано 5 разных записей: локальный черновик, не подтверждён сервером.».
Отказы choose: «Запись уже выбрана.», «В черновике уже пять записей.»,
«Запись отсутствует в каталоге.», «Каталог недоступен; выбор не изменён.».
Они не меняют draftRevision. Успешный remove/clear/choose возвращает обычный message
с учётом complete. При отсутствии id remove: «Запись не выбрана.».

Revision читается до body и проверки полной формы, old/duplicate body/keys не читаются.
После принятия нового revision разбор закрывает доступ к draft/choose до commit.
Внешние getters проверяются generation; выбор из getter revision отклоняет старый
update без перезаписи нового локального выбора. Exact schema проверяется до/после copy
сравнением массивов имён, не неоднозначным объединением через delimiter.

После invalid попытки choose/remove/clear сохраняют объяснение снятия черновика.
Если новый каталог снял выбор из-за версии/удаления, message объясняет причину
и просит выбрать заново; это не автоматический новый выбор. Invalid reentrant update
меняет generation и блокирует старый in-flight commit. Length массива читается
один раз до bounded decode и проверяется после, не используется подвижная граница.
