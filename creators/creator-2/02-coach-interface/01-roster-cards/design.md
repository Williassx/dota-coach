# C2-02-01: локальный просмотр карточек игроков

Пользователь поручил продолжать самостоятельно. Нативный фундамент ещё открыт;
следующий независимый результат — исходники карточек Panorama и проверка локального
выбора. Объём и архитектуру рассмотрели соответствующие критики до кода.

## Границы

Игрок, герой, позиция и происхождение профиля отображаются отдельно. Выбор своей
карточки означает просмотр и подсветку, а не управление героем. Свой мёртвый игрок
доступен для просмотра; чужой, неподдерживаемый или профиль неизвестного происхождения
не выбирается. Состав, тактика, приказы, камера и полный экран матча сюда не входят.

Общий контракт C1-01-03 остаётся условием серверной интеграции и окончательной
приёмки. Внутренний input модели представления не является сетевым протоколом;
будущий преобразователь серверных данных будет отдельным слоем. Карточки не читают
и не отправляют GameEvents, не выбирают юниты и не назначают режим AI/MANUAL.

## Внутренняя модель

ES5, без npm и Node API в игровых файлах. DotaCoachRoster.create() возвращает
replace(rows), select(id), clearSelection(), view() и dispose(). До пяти записей.
replace отклоняет неверный список целиком и сохраняет прежние данные/выбор;
адаптер сообщает, что список не обновлён. Пустой список очищает представление.

Каждая запись содержит только следующие поля:

| Поле | Допустимый ввод |
|---|---|
| id | Устойчивый уникальный ключ карточки: строка 1–64 символа без пробельных краёв; не playerId/entityIndex |
| playerName | Непустая строка до 64 символов |
| heroName | Непустая строка до 64 символов либо null для неназначенного героя |
| role | Целое число позиции 1–5 |
| source | synthetic, measured, estimate, unknown; происхождение профиля, не URL |
| side | own, opponent |
| availability | alive, dead, unsupported |

Недопустимые enum/поля, дубликаты id и более пяти записей отклоняют обновление.
Изменение длины входного массива во время копирования также отклоняется целиком;
цикл ограничен исходной длиной.
Входы копируются; view возвращает независимые карточки с русскими подписями,
selected/selectable и причиной недоступности. Измеренные признаки и оценка модели
не означают подтверждённого сходства с реальным человеком.

Выбор хранится по id, сохраняется при перестановке и переходе alive→dead;
удаление, смена стороны/поддержки/происхождения на неизвестное сбрасывают выбор.
Старый обработчик проверяет актуальную запись по своему id, а не номеру слота.
После dispose замена/выбор не действуют.

## Panorama и явная демонстрация

Адаптер DotaCoachRosterPanels.bind(root) находит пять заранее заданных слотов
и статус. Методы replace/select/clearSelection обновляют только текст, доступность
кнопок и класс выбранной карточки. Label.html=false; имена не подставляются в markup.
При ошибке рендеринга освобождаются обработчики, кнопки скрываются и отключаются;
если статус доступен, он сообщает о недоступности просмотра. Старые callbacks
не изменяют закрытый контроллер. isDisposed():bool сообщает только о закрытии адаптера.
Перед привязкой проверяются все необходимые панели.

Один XML roster_cards_demo.xml явно подключает отдельные синтетические fixtures
и демонстрационный bootstrap. Модель и адаптер сами fixtures не подставляют.
Это небольшой список для просмотра, не готовый экран матча или выбор состава.
Bootstrap хранит контроллер в отдельном ключе GameUI.CustomUIConfig и освобождает
предыдущий при перезагрузке. Проверка IsValid/isDisposed через Schedule освобождает
его после закрытия контекста или адаптера на следующем тике, не позднее 0.25 секунды
при работающем планировщике. Поведение этих API в движке ещё требуется проверить.

API сверены с [декларациями ModDota](https://github.com/ModDota/TypeScriptDeclarations/tree/df7722b560d5c616f7b2f6be42480aa5053baec8):
FindChildTraverse, IsValid, SetHasClass, SetPanelEvent/ClearPanelEvent,
visible/enabled, Label.text/html, CustomUIConfig и Schedule/CancelScheduled.
Это community reference, не фактическая версия Windows. Чужой код и изображения
не переносятся. Старый manifest упаковки 01-фонда остаётся неизменным.

## Приёмка облачной подготовки

Реальные игровые JS исполняются через node:test/vm с моделью только Panorama API.
Проверяются локальный выбор, dead/чужой/unsupported/unknown, перестановка/удаление,
неверный ввод, внешняя мутация, старые callbacks, ошибки/освобождение и отсутствие
вызовов управления. XML разбирается, пути/слоты/порядок scripts сверяются.
Нативный рендеринг, клики карты и серверная интеграция не объявляются выполненными.

## Расширение для C2-02-03, 9 октября 2026 года

View дополнен availableForOrders, отдельным от selectable. Bind принимает
необязательный callback с копией выбранного view/null, проверяет закрытие после
него и отклоняет вторую живую привязку того же root. Подробности — в
[спецификации координатора](../03-control-input/design.md). Приёмка карточек
в Dota остаётся открытой; callback не является серверным событием.
