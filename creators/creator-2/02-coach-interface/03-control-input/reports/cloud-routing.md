## Изменения

Создан ES5-координатор существующих roster/orders. Он связывает выбор карточки
с адресатом, отдельно принимает контрольные снимки и владеет общим lifecycle.
Модели/адаптеры расширены в своих исходных папках; копии не создавались.
XML/CSS, demo, сервер и foundation manifest не менялись.

Мёртвый игрок доступен для просмотра, но ограничение карточки блокирует намерения
даже при старом alive или новом AI контрольном снимке. Без снимка режим неизвестен;
без переходника кнопки отключены. Выбор/обновление не отправляют приказ.
Смена/remove/null сохраняет unresolved/unknown запрос; фоновый снимок не перехватывает
выбор. Старые кнопочные callbacks защищены поколением отображения orders.

Частичные ошибки bind/watch освобождают оба адаптера. Root имеют одного владельца;
повторный bind не меняет обработчики. Проверка перед send/report закрывает пару,
если другой root уничтожен/адаптер закрыт ещё до watcher. Dispose отменяет события
и таймеры; callback выбора получает независимую копию и не оживляет закрытый UI.

Нет игрового транспорта, кликов карты, MANUAL-запроса, реальных профилей или обучения.
Синтетические fixtures существуют в тестах; общий экран не установлен в Tools.

## Ревью и оставшаяся работа

Дизайн до кода рассмотрен по объёму и архитектуре. Зафиксированы gate при фоновом
снимке, откат частичной привязки, scoped send/report, проверка закрытия после callback
и единственный владелец root; эти гарантии проверяются отдельными сценариями.

Пять направлений рассмотрены read-only:

- Объём: сервер/общий контракт/права не изменены, зависимости и второй владелец сохранены.
- Архитектура: getter входа мог закрыть адаптер во время копирования, после чего
  старый update восстанавливал кнопки либо перезаписывал новую привязку root.
  Автор воспроизвёл три сценария RED; добавлены closed перед commit roster и
  available после операций модели/до publish обоих адаптеров. Повторное ревью
  подтвердило исправления и 26/26 без новых существенных замечаний.
- ИИ: выбор не создаёт AI/MANUAL/epoch, gate только ограничивает команды,
  происхождение данных и открытая серверная авторизация сохранены.
- Осуществимость: независимо пройдены 85/85 до исправления (22+28+35), проверены
  ES5 и существующие API. Новые XML/BLoadLayout/игровой транспорт не добавлены.
- UX: подтверждённых регрессий нет, замечание о повторном использовании cache
  после remove/re-add зафиксировано как политика последнего известного снимка.
  Stable id не переиспользуется для другого игрока в экземпляре/матче; актуальные
  права проверяет сервер. Отдельный сценарий сохраняет MANUAL и отвергает старый AI.

Проверены синтаксис пяти изменённых/новых игровых JS, 931 локальная Markdown-ссылка
и README всех новых каталогов; ошибок нет. git diff --check прошёл. Эти проверки
не прибавляются к числу сценариев. Команда добавлена только в start_skill;
сохранение черновика подтверждено, requires_publish=true. Остальные настройки
не менялись; активация требует рассмотрения/сохранения и публикации в настройках среды.

Приёмка «клик панели не вызывает неожиданный приказ карте» остаётся открытой:
нужны общий HUD без demo, реальный серверный переходник/контракт, Windows/Source 2,
mouse/hittest и рассмотрение вторым равноправным владельцем. Пять ИИ-критиков его
не заменяют. Восстановление серверных запросов после reload ещё не реализовано.
