# C2-02-03: связь выбора карточки и адресата приказа

Пользователь поручил автономное продолжение создателя 2. Подготавливаем координатор
существующих модулей C2-02-01/02, без серверных команд и без присвоения MANUAL.
Общие контракты, нативный HUD, карта и приёмка остаются открытыми.

## Решение

Копирование карточек/приказов в третий модуль создало бы расходящиеся реализации.
Глобальный обработчик мыши потребовал бы непроверенных координат/правил Dota.
Выбран небольшой координатор уже загруженных панелей: он связывает локальный
выбор с адресатом, а контрольные снимки поступают независимо. Новый общий XML
и загрузка/компиляция разметки определяются при нативной интеграции; исходники
существующих представлений здесь не копируются.

## Минимальные расширения существующих модулей

- Карточка view получает availableForOrders: own, alive, поддерживается,
  известное происхождение. Это ограничение UI, не серверное разрешение.
- DotaCoachRosterPanels.bind(root, onSelection?) сообщает независимую копию
  выбранной карточки либо null после успешного replace/select/clearSelection.
  При ошибке callback/рендеринга закрывается; без callback старый API сохраняется.
- DotaCoachOrders добавляет updateRecipient(snapshot):bool без смены выбора и
  selectRecipient(id, playerName, allowIntents):bool. Выбор id без контрольного
  снимка показывает неизвестный режим. allowIntents строго boolean, не меняет mode
  и только ограничивает canIssue; прежний setRecipient(snapshot) сохраняется.
- DotaCoachOrderPanels предоставляет те же два метода с рендером и прежним cleanup.
  update другого адресата обновляет его epoch/ревизию и при необходимости снимает
  отслеживание старой эпохи, сохраняя выбранного игрока. Общая версия в model одна.

## Координатор

DotaCoachInputRouting.bind(rosterRoot, ordersRoot, send?) возвращает
replaceRoster(rows):bool, updateControl(snapshot):bool, select(id):bool,
clearSelection():bool, dispose():void, isDisposed():bool.

Orders создаётся первым, затем roster с callback. Выбор передаёт id/имя/ограничение
профиля; он не создаёт mode/epoch/приказ. Мёртвого можно просматривать, но нельзя
послать намерение, даже если контрольный снимок ещё говорит alive. Отсутствие
снимка или переходника блокирует команды. MANUAL/INACTIVE не назначаются кликом.

Смена/удаление/недоступность выбранной карточки синхронизирует адресата без отмены
уже отправленного запроса. Незавершённый/unknown запрос сохраняет общую блокировку.
Фоновый снимок другого игрока не перехватывает выбор; старые epoch/revision не
откатываются. Старые callbacks приказов защищены поколением отображения.

Контрольный cache действует внутри одного экземпляра/матча. Remove/null снимает
выбор, но не удаляет известный снимок: возвращающийся тот же stable id использует
последний известный режим, без нового подтверждения. Производитель данных должен
сохранять идентичность id, передавать изменения epoch/revision и создавать новый
контроллер для нового матча; сервер проверяет актуальные права перед исполнением.
TTL и синхронизация после reload определяются общим контрактом, здесь не выдумываются.

send оборачивается проверкой живых дочерних контроллеров перед вызовом переходника.
Ошибка одного модуля закрывает оба; watcher 0.25s проверяет оба контекста и
isDisposed. dispose отменяет свой watcher и освобождает дочерние обработчики/таймеры.
Без send переходник не подставляется. Синтетические данные существуют только в тестах.

Поздний report тоже проверяет оба root/контроллера до передачи в orders. Callback
выбора при начальном bind обращается только к уже созданному orders; после callback
адаптер повторно проверяет, не закрылся ли он. Каждый roster/orders root принадлежит
одному живому адаптеру: повторный bind отклоняется, dispose освобождает владение.
Скрипты загружаются по одному разу; отдельные demo на этих же панелях не запускаются.

## Граница ввода мыши

Клик карточки — просмотр/адресат; клик OrderMove/OrderAttack — явно выбранное
намерение фиксированной цели сцены. Координатор не подписывает GameUI.SetMouseCallback,
не читает координаты/юниты и не вызывает GameEvents/приказы Dota. Родительские
root имеют hittest=false в существующей разметке; попадание/распространение кликов
должны проверяться в клиенте, Node этого не доказывает.

Запрос ручного вмешательства и произвольные цели остаются C2-05; общий контракт
определит корреляцию, авторизацию и возврат ИИ. Приёмка «клик панели не вызывает
приказ карте» целиком требует реального HUD/Dota и второго равноправного владельца.
