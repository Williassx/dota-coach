# C2-01-01: обследование интерфейсной среды

Пользователь выбрал роль создателя 2 и подтвердил, что клон
`D:\AI\dota2coach` существует и открыт в локальном Codex. Здесь выполняется
его интерфейсный фундамент. Облачная сессия остаётся Linux: наличие локального
клона подтверждено пользователем, доступ к его терминалу не подтверждён.

## Результат

Один помощник Python 3.9+ со стандартной библиотекой составляет инвентаризацию
Panorama в найденных установках Dota. Чтение Git и библиотек Steam использует
[существующий помощник создателя 1](../../../creator-1/01-foundation/01-environment-audit/tools/inspect_environment.py),
без копирования и изменения его исходника. Можно явно передать корень установки
через `--dota-root`; по умолчанию используется обнаружение Steam.

Помощник обследует только `content/dota_addons/<addon>/panorama` и
`game/dota_addons/<addon>/panorama`. XML/JS/CSS помечаются как исходные ресурсы,
VXML_C/VJS_C/VCSS_C — как скомпилированные. Положение в game/content не определяет
автора или наличие исходников. Наличие файлов не доказывает запуск Tools.
Упакованные ресурсы не извлекаются; отсутствие открытых файлов не означает,
что Workshop Tools отсутствуют.

Обход ограничен числом просмотренных записей и примеров файлов. Лимит записей
общий для content/game одной установки; учитываются промежуточные каталоги и
все перечисленные аддоны, включая аддоны без Panorama. Перечисление потоковое,
без предварительного list/sorted всего каталога; обход итеративный, без зависимости
от глубины стека Python. Символические ссылки, NTFS
junctions/reparse points и переходы за пределы установки пропускаются на каждом
промежуточном уровне и внутри Panorama; в Python 3.9 используются атрибуты lstat,
а не отсутствующий Path.is_junction. Отчёт показывает ограничения
и ошибки чтения. Содержимое ресурсов, origin и значения окружения не выводятся.
Каталоги Steam/Dota и Git не изменяются. `--output` создаёт новый JSON и сохраняет
существующий файл. Персональные локальные JSON исключены из Git.

## Границы

Это диагностический инструмент, а не сборка или игровая панель. Он не создаёт
аддон, не устанавливает зависимости, не запускает игру и не меняет управление
героем. `runtime_verified` всегда false. Итог C2-01-01 требует локального отчёта,
проверки путей Tools и рассмотрения создателем 1.

Альтернативы: ручное перечисление путей хуже воспроизводится; копия общего
обследователя создаёт два источника; сканирование диска выходит за текущую задачу.
Поэтому выбран ограниченный помощник с повторным использованием существующего.

## Проверки

Проверить реальные временные каталоги: отсутствующая установка; исходные и
скомпилированные ресурсы; ссылка за границу; ограничение обхода; неизменность
файлов; сохранность старого отчёта; обнаружение установки через Steam.
Отдельно проверить в Windows реальные пути и процесс открытия шаблона Tools.
