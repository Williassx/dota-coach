# Автономное продолжение создателя 2 на Windows

Пользователь поручил вести работу самостоятельно, без его ручного исполнения
команд. Это инструкция агенту для подключённой Windows-среды, а не поручение
пользователю. Клон `D:\AI\dota2coach` уже существует по его подтверждению;
повторное клонирование и вопросы о пути/ОС не требуются.

## Проверка доступного канала

Текущая облачная среда — Linux. Открытие локального Codex само по себе не даёт
этой задаче доступ к Windows. До локальных команд проверить, что исполняющий
терминал действительно Windows и существует указанный клон. Не считать открытие
панели Codex удалённым исполнением и не обращаться к папкам других проектов.

При отсутствии канала продолжать независимые исходники/проверки в облаке;
фиксировать нативный прогон как непроведённый. Не перекладывать рутинные команды
на пользователя и не выдавать модель движка за запуск Dota.

## Действия исполнителя при доступном Windows

1. Прочитать AGENTS.md, creators/creator-2/AGENTS.md и материалы 01-foundation.
2. Проверить незакоммиченные изменения и origin; получить актуальный origin/main.
   Обновлять рабочую ветку только fast-forward, сохраняя пользовательские файлы.
   Не удалять, не сбрасывать и не прятать изменения автоматически.
3. Проверить Python 3.9+ через доступный py/python; при его отсутствии сначала
   обследовать Steam/манифесты вручную, затем подготовить интерпретатор.
4. Выполнить обследователь C2, оставить локальный JSON вне Git, записать только
   необходимые факты в [workspace-audit.md](workspace-audit.md).
5. Исследовать реально установленный шаблон и компиляцию, подтвердить отдельные
   addon roots и способ запуска Tools. Не заменять существующие аддоны.
6. Уточнить [план Panorama](../../02-panorama-capability/implementation-plan.md)
   по этим фактам; упаковать исходники по рассмотренному manifest. Серверный ping
   остаётся ответственностью создателя 1, совместный запуск — после обработчика.
   До интеграции агент запускает read-only проверяющий из
   [инструментов упаковки](../../02-panorama-capability/tools/README.md) с фактическим
   output сборщика; соответствие исходникам не заменяет компиляцию/приёмку Tools.
7. Провести нативные сценарии и рассмотрение другим создателем. Не закрывать
   подпункт по факту удачного JSON или облачных тестов.

## Команды для агента в Windows PowerShell

Исполнитель открывает PowerShell в этом проекте. Нужен установленный Python 3.9+;
в облаке он есть, наличие на Windows ещё не проверено. Если команда `py` отсутствует,
агент проверяет доступный `python` и его версию; файлы Steam можно
обследовать вручную до подготовки интерпретатора.

```powershell
Set-Location 'D:\AI\dota2coach'
py -3 creators/creator-2/01-foundation/01-workspace-audit/tools/inspect_ui_workspace.py
```

Сохранение нового отчёта (каталог reports уже предусмотрен):

```powershell
$uiReport = 'creators/creator-2/01-foundation/01-workspace-audit/reports/windows-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-local.json'
py -3 creators/creator-2/01-foundation/01-workspace-audit/tools/inspect_ui_workspace.py --output $uiReport
```

Если Steam не обнаружен, добавьте `--steam-root` с его фактическим путём.
Если известно расположение Dota, добавьте `--dota-root` с её фактическим корнем
(родителем game/content). Пути Steam не заменяйте догадками.

Код выхода 0 означает, что инвентаризация составлена; он не означает готовность
Tools. `runtime_verified: false` остаётся таким до отдельной проверки клиента.
`truncated: true` означает частичный список; ссылки/reparse points пропущены.
Существующий отчёт не переписывается. Не публикуйте полный локальный JSON.

Нативная приёмка кнопки и ответа: [план следующей части](../../02-panorama-capability/implementation-plan.md).
