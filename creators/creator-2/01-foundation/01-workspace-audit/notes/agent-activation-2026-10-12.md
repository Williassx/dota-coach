# C2-01-01 — Подключение всех 175 ролей

Дата: 12 октября 2026 года. Ведущая роль: 173; автор реестра — создатель 2.
Проверяющий владелец: создатель 1, его рассмотрение остаётся открытым.

## Основание и граница

Пользователь поручил использовать весь каталог агентов по правилам репозитория,
продолжать самостоятельно и учиться на своих действиях. Каталог уже содержит
175 специализаций: новые номера и дублирующие роли не добавляются. Реестр связывает
каждую роль с этапом, владельцем, условием подключения и проверяемым результатом.
Это покрытие и готовность к назначению; запись не означает запуск 175 процессов,
готовую функцию, пройденную нативную приёмку или обучение весов модели.

## План изменения и приёмка

1. Сопоставить полный каталог и быстрый индекс; сохранить номера и названия.
2. Для каждого номера 1–175 закрепить этап P00–P13 и библиотеку владельца.
3. Обновить только корневой AGENTS.md, docs/agents.md, Агенты.md и два общих файла
   политики: разрешить полезные самостоятельные группы по этапам в доступных слотах.
4. Проверить одинаковые уникальные номера 1–175, названия, JSON и локальные ссылки.
   Эти проверки документов не являются сборкой Dota или source-регрессией игры.
5. Передать результат основному исполнителю для журнала/учёта и второму владельцу
   для рассмотрения. Изменения игрового кода, запуск Dota, commit и push вне задания.

## Обозначения и порядок

- `available` — роль может выполнить ограниченную локальную задачу сейчас, например
  аудит, спецификацию, проверку источников или сопровождение; результат ещё надо получить.
- `planned` — назначение следует после зависимостей из README/согласования спецификации;
  независимые локальные части допускаются, продуктовая приёмка остаётся открытой.
- `blocked` — задан явный gate: отсутствующий runtime/данные/принятое расширение.
  Это локальная запись зависимости, а не запрет исследования и не отказ правообладателя.
- C1/C2 — равноправные владельцы. В строке один ведущий; второй рассматривает результат.
  Связанный ID другого отдела задаёт интерфейс/проверку, не право редактировать его файлы.
- Этапы P00–P13 — цели продукта из дорожной карты; ID C1/C2 — маршруты библиотек.
  Для карьеры/редакторов P13 пока есть только общие задачи: новый подпункт создаётся
  после согласования объёма по WORKFLOW, существующие номера не переиспользуются.
- Одновременно в этой среде доступны максимум четыре процесса всего: основной и
  до трёх помощников. Перед группой назначаются разные файлы и самостоятельные результаты;
  зависимые результаты идут последовательно, свободный слот используется повторно.
- Обсуждение ведёт основной исполнитель. Роли 173–175 выполняются без постоянного
  отдельного процесса. Один критик по завершении подпроекта; он не заменяет создателя 1.
- Любая фактическая активация фиксируется в журнале C2 и agent-usage.jsonl основным
  исполнителем: роли, результат, файлы, команды и ограничения. Нет usage — null.
- После успеха/сбоя сохраняется короткий урок с доказательством и правилом предотвращения,
  перед похожим действием он читается. Не повторять ошибку без нового проверяемого основания;
  проектные заметки не являются глобальной памятью Codex и не меняют модель.
