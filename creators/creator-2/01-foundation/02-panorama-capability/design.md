# C2-01-02: кнопка и ответ сервера

**Статус:** рассмотренная минимальная спецификация; подготовка исходников разрешена
поручением пользователя продолжать самостоятельно. Нативная приёмка остаётся открытой.
**Цель:** в клиенте Dota показать небольшую диагностическую панель и доказать
обмен Panorama → Lua → тому же клиенту. Это первый шаг отдела интерфейса.

Панель содержит название «Dota Coach — проверка связи», кнопку «Проверить связь»
и текст результата. Нажатие отправляет только диагностическое событие.
Во время ожидания кнопка недоступна. Подтверждение показывает «Сервер ответил»;
тайм-аут — «Ответ не получен — повторить проверку». Область вне панели не должна
перекрывать карту. Полный тренерский экран появится в последующих разделах.

Серверный обработчик принадлежит создателю 1, UI — создателю 2. UI не меняет
режим героя, выбранного игрока, ИИ или приказы. Временное ручное управление
проверяется позже, в C1-04 и C2-05. Успех ping не подтверждает его работу.

## Варианты и выбор

- Только локальная кнопка проверяет отображение, но не соединение.
- Использование готового большого шаблона добавляет зависимости и чужую механику.
- Минимальные XML/CSS/JS и отдельный Lua-ответ проверяют нужный механизм напрямую.

Выбран третий вариант: исходники подготавливаются в облаке, установка — после
обследования локального шаблона. TypeScript,
npm и исходники стороннего шаблона в проект пока не добавляются.

## Независимая подготовка в облаке

По поручению «всё сам, меня не вмешивай» исходники XML/CSS/JS можно подготовить
до доступа к Windows. Это не требует знания абсолютного пути установки:
ресурсы используют относительные пути Panorama. Установка, компиляция Source 2
и приёмка выполняются только по фактическим локальным путям. Команды пользователю
для ручного исполнения не являются следующим обязательным шагом.

JS разделяется на состояние диагностической попытки и привязку к Panorama.
Первая часть получает транспорт/таймер/отображение как зависимости; вторая
использует GameEvents, $.Schedule и проверенные в открытых декларациях методы
Panel. Это позволяет проверять настоящий код, заменяя только недоступный движок.
Такие проверки доказывают обработку сообщений, но не рендеринг или совместимость Dota.

GameUI.CustomUIConfig хранит счётчик ID и текущий экземпляр панели между её
перезагрузками. Новый экземпляр освобождает предыдущий. Нельзя выдумывать событие
ondelete: используются явное освобождение, проверка Panel.IsValid и ограниченный
таймер наблюдения. Его поведение при разрушении контекста проверяется в Dota отдельно.
Один клиент держит только одну диагностическую панель и подписку.
Ошибка отображения прекращает попытку и освобождает подписку, таймеры и обработчик
кнопки; панель переходит в недоступность, если резервное отображение возможно.

## Критерии

1. Панель видна в нативной Dota, есть журнал загрузки, ошибок XML/JS нет.
2. Одно нажатие создаёт один запрос; сервер пишет тот же request_id и возвращает
   ответ только отправителю. UI показывает успех только после этого ответа.
3. Без обработчика получается тайм-аут, повторный запрос использует новый ID.
4. Старый/чужой/неизвестной версии ответ не завершает текущий запрос.
5. Повторная загрузка UI не дублирует подписки; закрытие сцены убирает таймеры
   и подписки через проверенный в установленной версии механизм.
6. Карта вне панели принимает штатный ввод; проверка не изменяет героя.

Для первого прогона предлагается тайм-аут связи 2 секунды реального времени.
Это параметр диагностического UI, не длительность ручного вмешательства.
Подписка создаётся до отправки запроса. Поздний ответ после тайм-аута сохраняется
только в диагностическом журнале и не превращает повторный запрос в успех.
Успех и отказ одинаково отменяют таймер и сбрасывают ожидаемый ID; новая проверка
доступна после обоих. Только активный запрос может изменить результат; дубликат
ответа и старый таймер не заменяют уже показанный итог.

Сигнатуры подтверждены в открытых материалах сообщества, но не в пользовательской
сборке Dota. Источники и незавершённые проверки: [panorama-probe.md](notes/panorama-probe.md).
Примеры сообщения пока являются [предложением](../03-interface-contract/notes/ui-contract-input.md).
