# C2-01-02: план нативной проверки

**Статус:** подготовлен к уточнению после локального аудита; не план с проверенной
командой сборки. **Спецификация:** [design.md](design.md).
**Источник API:** [зафиксированные материалы](notes/panorama-probe.md).
**Владелец:** создатель 2 — XML/CSS/JS; создатель 1 — ранний Lua ping в C1-01-02.

## 1. Завершить входы Windows

Из C2-01-01/C1-01-01 получить реальную установку, шаблон, manifest, способ
компиляции и отдельную сцену. В этот документ внести подтверждённые конечные пути
и команду сборки/запуска. Не создавать исходники по непроверенной установочной схеме.

## 2. Рассмотреть диагностический обмен

Вместе рассмотреть [имена/поля ping](../03-interface-contract/notes/ui-contract-input.md),
определение отправителя и обработку повторной загрузки. Это малый обмен для
ранней проверки, а не ожидание полного игрового контракта C1-01-03.
Создатель 1 готовит обработчик независимо от UI после аудита; после этого
владельцы соединяют части. Полная сцена ИИ и ручного управления здесь не требуется.

## 3. Реализовать UI в этом подпункте

Предлагаемые **исходные** файлы после уточнения плана:

- `src/panorama/layout/custom_game/custom_ui_manifest.xml` — только наша панель.
- `src/panorama/layout/custom_game/coach_probe.xml` — заголовок, кнопка, статус.
- `src/panorama/styles/custom_game/coach_probe.css` — небольшая область UI.
- `src/panorama/scripts/custom_game/coach_probe.js` — подписка до запроса,
  корреляция ID, тайм-аут, освобождение обработчиков через проверенный механизм.

До создания src добавить его README и ссылку в карточку. Единственные исходники
остаются здесь; отдельный рассмотренный manifest упаковки сопоставляет их с
фактическими addon roots. Сторонний шаблон и его модификатор героя не копировать.

## 4. Проверить поведение в Dota

1. Загрузить отдельную сцену, убедиться в отсутствии XML/JS ошибок.
2. Нажать кнопку: один запрос, тот же ID в серверном журнале, адресный ответ,
   видимое подтверждение. Зафиксировать сборку и оба журнала без SteamID.
3. Проверить отсутствие обработчика: тайм-аут и новая попытка с другим ID.
4. Проверить устаревший ID/другую версию/повторную загрузку: нет ложного успеха
   и дублирования подписок. Если доступен второй клиент, проверить адресность;
   без него проверка адресности для двух клиентов остаётся непроведённой.
   Проверить отказ и успех: таймер отменён, итог не меняется дубликатом или старым
   таймером, повторная проверка разрешена; отказ сохраняется дольше тайм-аута.
5. Проверить штатный ввод карты вне панели и отсутствие изменений героя.
6. Записать результат каждого сценария в notes/panorama-probe.md; передать
   создателю 1, затем обновить README. При ошибке сохранить её и исправить причину.

Пока Windows-данных и Lua-обработчика нет, допустимо исследование и уточнение
документов. Панель, сборка и нативная приёмка не объявляются выполненными.
