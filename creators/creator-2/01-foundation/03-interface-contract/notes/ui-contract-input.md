# C2-01-03: предложение от интерфейса

**Статус:** подготовлено до нативного прогона; не общий утверждённый контракт.
**Получатель:** создатель 1, C1-01-02 — ранний ответ; C1-01-03 — общий контракт.
**Автор области:** создатель 2. Обсудить обеими сторонами после аудита.

## Минимальный диагностический обмен

Предлагаемые имена: `dota_coach_probe_request` и `dota_coach_probe_result`.
Запрос содержит только `protocol_version: 1` и `request_id` (непустая строка,
до 64 символов, уникальная между попытками и перезагрузками UI в данной сессии).
Генератор ID выбирается после проверки возможностей локального JS; ID служит
корреляции, а не авторизации. PlayerID и режим героя в запрос не входят.

Ответ возвращается только проверенному отправителю, содержит те же version/ID,
`status: "ok" | "rejected"`, `reason: "none" | "unsupported_version" | "invalid_request"`.
`ok` означает лишь, что обработчик получил диагностический запрос. Это не
подтверждение действия героя, режима MANUAL или пригодности персонального ИИ.
Некорректный запрос без пригодного ID может быть отклонён без адресного ответа;
клиент тогда получит тайм-аут. Новые поля требуют совместного рассмотрения.

Примеры: [запрос](../fixtures/probe-request.json), [успех](../fixtures/probe-result-ok.json),
[отказ](../fixtures/probe-result-rejected.json). Они искусственные, без данных игроков.
Это формы сообщений для рассмотрения, не исполняемый протокол.

## Состояния отображения

| Состояние | Триггер | Поведение |
|---|---|---|
| Готово | Панель и подписка созданы | Разрешить проверку |
| Ожидание | Отправлен запрос | Запомнить ID, запретить повторное нажатие |
| Связь подтверждена | Соответствующий ответ ok | Отменить таймер, сбросить ожидаемый ID, показать ответ, разрешить новую попытку |
| Отказ | Соответствующий ответ rejected | Отменить таймер, сбросить ожидаемый ID, показать причину, разрешить новую попытку |
| Ответ не получен | Локальный тайм-аут | Не считать серверное действие отменённым; разрешить новый ID |
| Недоступно | Панель/соединение закрыты | Отменить таймер, освободить подписку, сбросить ожидание |

Ответ с неизвестной версией или чужим/устаревшим ID не подтверждает текущий запрос.
Поздний результат диагностической попытки попадает только в журнал. Тайм-аут UI
не является приказом серверу и не снимает игровой режим.
Таймер и ответ меняют UI только для активного запроса; тайм-аут тоже сбрасывает
ожидаемый ID. Дубликат ответа после завершения не меняет итог. Отказ не заменяется
тайм-аутом спустя две секунды; после успеха разрешена новая попытка.

## Требования для будущего игрового контракта

Это входные требования к C1-01-03, а не реализация C2-05:

- Выделение карточки локально отделено от серверного права управлять героем.
- Режим AI/MANUAL/INACTIVE, текущая эпоха управления и ревизия состояния приходят
  с сервера. UI не меняет режим оптимистически после клика.
- «Запрос получен», «разрешён», «выполнен», «отклонён» и «ИИ возобновлён» различимы.
  Атака разрешена — не значит, что цель поражена; попытка добивания — не гарантия.
- Каждое действие связывается с request_id, героем и эпохой; старое событие не
  завершает новое вмешательство. Причина отказа/возврата остаётся видимой.
- После перезагрузки UI запрашивает актуальное состояние, а не назначает AI локально.
- UI получает только допустимые наблюдения, без скрытых противников и будущих событий.
- Тип профиля (`синтетический`, `измеренный`, `оценка модели`) и ограничения данных
  отображаются явно; характер и мораль не выдаются за измерения матчей.

Политику длительности и приоритетов определяют владельцы по проверке сцены.
В [целевой спецификации](../../../../creator-1/01-foundation/02-addon-capability/probe-design.md)
5 секунд игрового времени остаются предложением; двухсекундный UI ping его не меняет.

## До закрытия подпункта

Нужен реальный результат C2-01-02 и рассмотренное создателем 1 предложение
интерфейса с примерами и отмеченными открытыми вопросами. Готовый общий игровой
контракт не является условием закрытия C2-01-03: его согласование — результат
C1-01-03, проверка игровых состояний — последующих серверных/UI задач.
Диагностический ping рассматривается отдельно для раннего прогона. Пять
ИИ-критиков не заменяют рассмотрение вторым равноправным владельцем.
