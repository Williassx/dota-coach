# Исполнение C2-05-03

[Родитель](README.md) · [Спецификация](design.md).
Основной исполнитель — создатель2; один финальный критик после всего реализованного
подпроекта, не во время планирования. Пользователя не привлекать к рутинным операциям.

## 1. Подготовить реальные входы

1.1 Прочитать опубликованные C1-04-01/02/03 и shared contract; сейчас это зависимость.
1.2 Зафиксировать настоящие event names/version/identity/session, порядок и источник
    времени. Не назначать эти значения самостоятельно в интерфейсной библиотеке.
1.3 Проверить различие ACK, разрешённого ввода, результата действия и возврата ИИ.
1.4 Сохранить малые синтетические fixtures по реальному контракту с explicit test label.
1.5 Подготовить cases ниже; неизвестные серверные правила оставить явно открытыми.

## 2. Реализовать локальный UI adapter

2.1 Один private instance, fixed captured actor, не дублировать Requests/Targets logic.
2.2 RED: accepted≠manual authority, cancel pending≠cancelled, timeout≠success.
2.3 RED: старое действие/поколение/герой/сеанс и неправильная последовательность
    не переносят результат или cancel на новый запрос; regression после reconnect.
2.4 RED: missing/invalid source очищает недостоверный результат; getters/reentry,
    dispose/old callbacks/busy проходят до caller reads. Нет скрытых игровых данных.
2.5 GREEN: minimal adapter, copied view, bounded history только если она необходима
    для подписей; unknown состояния показываются явно. Countdown только по контракту.

## 3. Реализовать native-facing панель и source пакет

3.1 Inert XML/CSS, plain labels и explicit binding; реальные callbacks по проверенному
    Panorama API. Требуемые узлы имеют одного владельца, cleanup закрывает входы.
3.2 Cancel handler disabled без настоящего порта/права; нет fake sender/auto cancel.
3.3 При отправке показывать ожидание с прежним actor, не переставлять actor при selection.
3.4 Tests на clear-beforeDTO, replaced/hidden nodes, exactly one handler, dispose/reopen.
3.5 Fixed source recipe с текущими bytes, generated scope отдельно от canonical files;
    registry/catalog update, targeted и один полный source run после завершения.

## 4. Матрица независимой нативной приёмки

| Сценарий | Что проверять отдельно |
|---|---|
| Успех атаки/добивания/deny | Фактический результат, не просто ACK/auto-attack старт |
| Отмена до приёма | Ответ cancel и отсутствие старого действия |
| Отмена после приёма | Остановка/завершение согласно C1 policy и отдельный AI return |
| Cancel повтор/поздний ACK | Один результат для прежнего action; новое не затронуто |
| Lease timeout | Серверное истечение, закрытие права и реальный возврат ИИ |
| Пауза/возобновление | Согласованное время без обнуления/продления по UI |
| Смерть/возрождение | Старое действие не выполняется после новой жизни |
| Скрытие/удаление цели | Цель недоступна; не подписывать скрытие как смерть |
| Отключение/reconnect | Актуальная проекция, старые callbacks не отправляют ничего |
| Замена героя/epoch/session | Старый lease/target/action не применяется к новому |
| Смена выделения во время cancel | Cancel остаётся у captured actor |
| Dispose/reopen | UI закрывается; реальные серверные последствия проверяются отдельно |

4.1 Сначала локальный аудит Windows/реальный шаблон/Source2; cloud VM не подменяет его.
4.2 Сохранить commands/build_id/native logs и фактическое подтверждение по каждому
    случаю, не заполнять результат из наличия исходников.
4.3 Финальный критик после готового подпроекта; находки воспроизвести/исправить.
4.4 Приёмка второго человеческого владельца отдельно; он не заменяется критиком.
4.5 Отметить только проверенные README действия, regenerate graph, journal, mandatory
    checks, guarded Git main push/remote/clean. Не отмечать native пункты заранее.
