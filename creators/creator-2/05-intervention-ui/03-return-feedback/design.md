## Назначение

Тренер видит назначенного игрока, состояние вмешательства, результат действия и
наблюдение управления раздельно. Успех добивания не означает возврата ИИ, отмена
запроса не означает отмены уже выполняющегося действия, скрытая цель не означает
смерть. Последний source block мыши — предложение, а не право управления.

## Что можно показать уже по локальным источникам

| Источник | Допустимая подпись | Чего он не подтверждает |
|---|---|---|
| MouseProposal | Предложение сформировано / действие ещё не выполнено | Исполнение, lease или право ввода |
| Request pending | Ожидается ответ | Переход в ручной режим |
| Request accepted | Запрос принят | Владелец управления, старт или завершение действия |
| Request mode-observed | Наблюдён ручной режим | Причина перехода или предоставленные права |
| Request cancelled | Источник сообщил отмену запроса | Остановка действия или возврат ИИ |
| Local expiry/not-sent | Ответ неизвестен / запрос не отправлен | Серверный timeout или успешная отмена |
| Targets non-ready | Цель недоступна; предложение снято | Смерть героя или завершение вмешательства |

Никакой строки «успешно» для ACK, локального времени или снятого UI. Нет остатка
lease без серверного источника. Обычный refresh/dispose не отправляет отмену.

## Будущее представление после общего контракта

Это требования к UI, не утверждённые имена полей, событий или методов сервера.

1. Адресат фиксируется при запросе; смена карточки не переносит cancel или результат.
2. Отдельные строки: запрос, действие, право управления/оставшееся время, причина,
   подтверждение возврата. Не сводить все состояния к одной зелёной кнопке.
3. Cancel click создаёт намерение и показывает ожидание. Повтор той же отмены
   блокируется, но исчезновение UI не отменяет намерение на сервере автоматически.
4. Подтверждённое завершение относится к одному действию/поколению/серверному сеансу.
   Источник обязан позволять отделять старую жизнь/героя/сессию от новой.
5. Опоздавший ответ не изменяет новое вмешательство. Переподключение запрашивает
   актуальную проекцию, не повторяет старое действие и не выводит старое «успешно».
6. Пауза и lease clock должны иметь согласованную семантику; frontend время не
   становится authority. Когда время недоступно — неизвестно, без выдуманного счётчика.
7. Возврат ИИ подтверждается отдельным авторитетным наблюдением для прежнего actor.
   Результат cancel и факт возобновления ИИ имеют отдельные состояния.
8. Смерть/отключение/замена героя прекращают допустимость ввода по серверной политике;
   возрождение не оживляет старый приказ. Частично выполненное действие показывается
   согласно фактическому исходу, без автоматического превращения в успех.

## Владение и входы

Создатель1: реальные action/lease/clock/identity/session/cancel/AI-return semantics,
серверные проверки и проекция разрешённого знания. Создатель2: UI state adapter,
plain labels, buttons/handlers, native tree/lifecycle, вывод причин. Владельцы равны.
Shared contracts меняются отдельной согласованной задачей, не этим документом.
Не создавать transport или поля «под предполагаемый сервер» до его контракта.

## Критерий продолжения реализации

Нужен реальный versioned contract и тестовый producer из C1-04-01/02/03, с
семантикой request/action/lease/cancel/return и правилами поздних событий. Затем
UI adapter может пройти RED/GREEN и source tests. Native compile/hittest/gameplay
и приёмка другого человеческого владельца остаются самостоятельными этапами.
