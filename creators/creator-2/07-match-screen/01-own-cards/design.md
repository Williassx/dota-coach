# Ранняя подготовка общего шаблона HUD

Пользователь поручил продолжение до остановки. Подготовленные карточки, приказы,
камера и наблюдение пока существуют отдельными компонентами. Следующий результат —
одна разметка для размещения этих компонентов и проверенный пакет их исходников.
Это ранняя подготовка до полного C2-07-01/C2-11-02, разрешённая INTEGRATION.md.

## Объём и варианты

Отдельные CustomUIElement для каждого компонента затруднили бы совместную привязку
root и могут изолировать контексты скриптов. BLoadLayout требует отдельного native
исследования. Выбираем один HUD layout с четырьмя scoped root и существующими
идентификаторами адаптеров, без автоматического bind. Единственные реализации JS
сохраняются в исходных библиотеках и загружаются в dependency order.

Создаём src/panorama/layout/custom_game/coach_hud.xml и custom_ui_manifest.xml,
src/panorama/styles/custom_game/coach_hud.css. Пять собственных карточек располагаются
снизу, приказы/камера/наблюдение справа. Центр не закрываем изображением карты:
нативный игровой мир остаётся за прозрачным root. Противников/покупки/голос/события
не имитируем. Графика Dota/портреты/данные не копируются.

## Контекст и ресурсы

HUD включает девять существующих definitions-only scripts: roster state/panels,
orders state/panels, input_routing, camera native/panels, targets state/panels.
Ресурсы demo/probe не входят. Новые XML/CSS дают отдельную runtime-кандидат разметку,
не копию JS или установку. Global IDs уникальны, root scopes CoachRoster/CoachOrders/
CoachCamera/CoachTargets содержат обязательные id своих адаптеров; labels html=false.
Родительский root hittest=false; только области потенциальных кнопок принимают клики.
Наблюдение hittestchildren=false. Нативный hittest/геометрия ещё не проверены.

При первом показе видны только честные пустые состояния: состав не получен,
адресат/режим неизвестны, камера не подключена, цель не выбрана. Карточки скрыты,
приказы отключены. XML не запускает JS через onload/run, scripts не autobind.
Включение кнопок, camera mapping и наблюдения требует явного будущего интегратора.
Существующий orders stub не выдаётся за готовые реальные приказы.

## Проверки и приёмка

Пакет в C2-11-02 использует единственные исходники по manifest. Проверяем dependency
order, отсутствие demo/bootstrap, scope IDs, plain-text/hittest и полный resource graph;
default foundation probe остаётся совместимым. Поведенческие suites повторяются.
Разметка/пакет не подтверждают компиляцию Source2, HUD appearance, native input,
сервер, реальные профили/героев или выполнение действий. Второй владелец открыт.

Покупки/намерения, противники/voice, серверные события, новый общий coordinator и
установку не добавляем этой задачей. UI-концепция остаётся в исходном подразделе.
